# Documentation guidance

- Put engineering change evidence in `docs/branch-reports/` and customer-facing material in `docs/customer/`.
- Use UTC-timestamped, lowercase, hyphenated filenames and never overwrite an existing generated document.
- Keep test evidence factual: distinguish checks that ran, checks that were skipped, and checks that are only recommended.
- Do not include credentials, private URLs, raw customer data, or internal implementation detail in customer-facing documents.
- Keep Markdown portable to Notion and similar hosted documentation tools.
